# 少参与漫剧制作指引：《狐假虎威：森林里的假大王》

> 交付目的：让你不必自己写剧本、逐镜想提示词、逐句配音和逐段剪辑，也能组织完成一部有开头、冲突、反转和结尾的漫剧。
> 检索与核对日期：2026-09-14。默认交付：**一集约90秒、9:16、1080×1920、中文、二维轻动态漫剧**。
> 本次交付是详细指引、完整改编剧本、机器可读分镜和本地合成脚本，**不是已经生成的正式成片**。没有调用付费模型、购买服务或发布视频。

## 0. 你只需要记住这一页

**推荐路径：古代故事重新编剧 → 固定角色参考图 → 逐句配音 → 参考图约束生成分镜 → 图片轻运镜 → 自动字幕与合成 → 人工终审 → 发布。**

- 不做逐帧动画，不做全片AI图生视频，不做强制口型同步。成片是“有角色台词、镜头叙事、连续画面和轻运镜的动态漫画”，不是流畅全动作动画。
- 不要求你手画、录音、安装十几个创作平台；主方案使用一个模型服务平台与本地合成工具。
- 让能够读写文件、访问已授权模型API、运行Python/FFmpeg的执行代理或制作人员承担机械工作。普通只有聊天能力的网页AI不能单凭提示词完成文件下载、渲染和发布。
- **你的三个检查点**：①首次确认预算/账号/风格；②只看一张角色拼图和约17秒样片；③看完整片并决定是否发布。若发生超预算、版权不清或反复失败，才额外询问你。
- 预计人工注意力：首次配置约15–30分钟，样片约5分钟，终审约5–10分钟；这些是工作量估计，不是承诺。无人值守运行时间取决于排队、网速、硬件与返工。

## 1. 网上选了什么剧本，为什么选它？

### 1.1 选定：《狐假虎威》的网络课本剧题材，重新编写成短漫剧

检索到了《狐假虎威》课本剧剧本合集，含旁白、狐狸、老虎和森林动物的对白及动作安排。[S1] 这提供了真实存在的**可舞台化剧本参考**，不是把搜索模型临时写出的示例冒充网上原作。

传播验证：

- 西瓜视频《儿歌点点动画故事〈狐假虎威〉狡猾的狐狸是怎么骗过老虎的呢？》页面抓取显示 **35.4万次播放**。[S2]
- B站《【成语故事动画】狐假虎威》页面抓取显示 **4.6万播放**，简介明确标注动画来源为中国华文教育网。[S3]

**“热门”的准确边界**：这里选择的是有数十万播放样本的经典常青题材，不是近期抖音漫剧榜单爆款；数字证明的是相关动画的传播，不是所引用课本剧网页的阅读量，也不保证新片会爆。未找到同时满足“现成短漫剧剧本、近期头部爆款、明确免费商用授权”的可靠样本，因此不虚构这种组合。

检索中也比较了《斩仙台下，我震惊了诸神》等现代头部漫剧；行业报道给出很高播放量，但它们涉及持续剧情、多角色、战斗和IP授权，不适合你第一次少参与制作。[S4] 本方案优先满足“简单且容易完整做出来”，不照搬头部作品。

### 1.2 如何从网络题材变成可制作剧本

| 网络课本剧常见形式 | 本案处理 | 制作收益 |
|---|---|---|
| 老虎抓到狐狸 | 改成老虎挡住去路 | 避免肢体接触和暴力画面 |
| 狐狸声称奉天帝之命 | 保留核心虚张声势冲突，台词重写 | 观众容易理解，故事不走样 |
| 多种动物一起逃跑 | 只用一只无对白小兔代表百兽 | 不生成复杂群戏，不增加音色 |
| 狐狸借老虎威风脱身 | 保留因果，镜头明确展示小兔看到老虎 | 反转靠画面而非全靠旁白 |
| 舞台串词、开场歌舞 | 全部删除 | 第一秒进入冲突 |
| 寓意说明 | 一句解释后加老虎迟来的醒悟 | 故事闭环、有喜剧尾声 |

### 1.3 版权怎么处理

古代故事依据《战国策·楚策一》“荆宣王问群臣”相关段落。[S5] 本案从古代情节重新创作对白与镜头；不复制现代课本剧的独创台词、译文、舞台编排，不下载现有动画画面、音乐、角色形象或配音来拼接。

古代故事本身与现代改编作品的权利不同。“网上能看”“免费下载”“注明出处”都不等于获准商用。画面采用原创动物设计；声音使用服务商允许相应用途的系统音色；不用真人/明星克隆声音；默认不使用背景音乐。字体也必须核实授权。

发布前保留模型服务条款、素材许可、生成时间、提示词、订单/用量凭据。若改为搬运网络剧本或现代小说，必须另取得涵盖改编、信息网络传播及商业用途等实际所需权利的授权。本节不是个案法律意见。

## 2. 成片规格与已经锁定的创作选择

| 项目 | 本案默认 |
|---|---|
| 片名 | 《狐假虎威：森林里的假大王》 |
| 受众 | 亲子及大众轻喜剧；不做恐怖与暴力表达 |
| 形式 | 二维绘本式动态漫画，配音驱动，镜头推进/拉远 |
| 时长 | 计划90秒；若实际配音较长允许镜头延长，目标90–105秒 |
| 镜头 | 15镜，单镜5–7秒计划值；最终以配音测量为准 |
| 角色 | 狐狸、老虎、小兔；小兔不说话 |
| 声音 | 狐狸、老虎、旁白，三个固定系统音色 |
| 场景 | 同一片白天森林小路；同一画风、服饰、光线 |
| 复杂度限制 | 每镜最多两个角色；无打斗、接触、复杂转身与群众 |
| 视频 | 1080×1920，30fps，H.264，yuv420p，MP4 |
| 音频 | AAC、48kHz、双声道；合成目标约-16 LUFS，真峰值目标≤-1.5dBTP，最终需复测 |
| 字幕 | 简体中文、白字黑描边、最多三行；本脚本按镜头整句显示，不是逐字卡拉OK |
| BGM | 默认无；以台词、停顿与剪辑节奏成立，避免音乐授权和混音返工 |
| 标识 | 画面显示“AI辅助生成”，发布时另按平台规则作AI声明 |

### 为什么不全片图生视频？

对本案而言，全片视频生成会新增：角色漂移、口型错误、短片衔接、动作失败和按秒计费。图片加小幅运镜的动作上限较低，但**更易稳定完成**。人物并不会因为相机推进而真的行走，这一点不作夸大宣传。

如果你明确要求流畅动作，可在基础版通过后，仅升级第01、06或08镜中的1–2镜；这会增加费用、等待和审核，不是完成基础版的前提。当前 `render.py` 只接收图片，不接收替换视频片段；升级需另改合成器或使用剪辑器，不能直接把MP4重命名成PNG。

## 3. 完整剧本与分镜：无需再让AI自由续写

下表为**本次重新编写的制作版**，不是网络剧本原文。第15镜是新增喜剧尾声。

| 镜号/计划时间 | 景别与画面 | 说话者与准确台词 | 表演/剪辑 |
|---|---|---|---|
| 01 / 00–05秒 | 森林中景；右侧老虎挡路，左侧狐狸后仰 | 老虎：抓到你了！今天的晚餐有着落了！ | 直接冲突，无片头Logo；慢推进 |
| 02 / 05–11秒 | 狐狸近景，举前爪，眼珠一转 | 狐狸：等等！我可不是普通的狐狸！ | 先慌后装镇定；慢推进 |
| 03 / 11–17秒 | 狐狸中景，昂首挺胸 | 狐狸：天帝派我来管理百兽，你也得听我的！ | 一本正经；慢拉远 |
| 04 / 17–23秒 | 老虎近景，歪头挑眉 | 老虎：就凭你？有什么证据？ | 怀疑；慢推进 |
| 05 / 23–29秒 | 狐狸指向小路，回头邀约 | 狐狸：跟在我后面走一圈，看看谁不怕我！ | 自信诱导；慢拉远 |
| 06 / 29–35秒 | 侧面全景，狐狸在左前，老虎在右后 | 旁白：狐狸走在前面，老虎半信半疑地跟着。 | 行走姿势定格；慢推进 |
| 07 / 35–41秒 | 小兔在灌木边抬头 | 旁白：路边的小兔抬起头，先看见了狐狸。 | 好奇，不恐惧；慢推进 |
| 08 / 41–47秒 | 右前小兔藏进灌木，左后老虎明显可辨 | 旁白：可一看清后面的老虎，它立刻躲了起来！ | 必须让观众看清害怕的原因；慢推进 |
| 09 / 47–53秒 | 老虎近景，疑惑地看左侧 | 老虎：咦？它怎么一看见你就跑？ | 误判；慢拉远 |
| 10 / 53–59秒 | 狐狸中景，叉腰昂头 | 狐狸：看见没有？这就是我的威风！ | 得意；慢推进 |
| 11 / 59–65秒 | 老虎让开小路，作请的姿势 | 老虎：原来你这么厉害！请，请先走！ | 客气、结巴；慢拉远 |
| 12 / 65–71秒 | 狐狸躲到分叉树后，按胸松气 | 旁白：狐狸趁机溜走，这才松了一口气。 | 冲突解决；慢拉远 |
| 13 / 71–77秒 | 小兔从灌木探头，表情无奈 | 旁白：小兔怕的，明明是狐狸身后的老虎。 | 真相点明；慢推进 |
| 14 / 77–83秒 | 解释性双人静态画面，小狐狸在前，大老虎在后 | 旁白：借着别人的威势吓唬人，就叫狐假虎威。 | 说明寓意；慢拉远 |
| 15 / 83–90秒 | 老虎特写，前爪指向自己，空路在后 | 老虎：等等！它刚才看的……好像是我？ | 后知后觉；尾句后留白；慢推进 |

**制作优先级**：实际配音、`production.json`、本表三者一致；修改台词必须先改JSON，再生成对应音频及字幕，不能让三份文案各自漂移。上述时间为计划，不应当拿固定90秒强行切断真实配音。

## 6. 素材生成的明确步骤

### 阶段1：锁定资产，不直接开始15次独立文生图

先生成4张资产：三角色各一张清楚的全身三分之四侧面定妆图、一个无人森林场景图。首轮各1张；确实不合格再针对性重试，不一次申请几十张候选。

**统一画风提示词**：

```text
原创二维绘本漫画，粗细统一的深棕描边，柔和赛璐璐色块，暖色调，
简洁背景，夸张清晰的表情，造型适合亲子轻喜剧，干净明确的轮廓。
不要模仿任何已有动画IP，不要文字、标志、对话气泡、分格漫画。
```

**角色提示词**：分别使用 `production.json.characters` 中的完整设定，追加：

```text
单一角色全身定妆照，三分之四侧面，姿势自然，完整显示耳朵、四肢和尾巴，
纯米色背景，角色周围留白。全图只出现一个角色，不画多视图和多个姿势。
```

- 狐狸：橙红毛、白口鼻与胸腹、白尾尖、绿色小围巾、仅一条蓬松尾巴。
- 老虎：橙黄毛、黑条纹、白口鼻与肚皮、蓝色短马甲、圆脸，不恐怖。
- 小兔：白毛、粉耳、红背包，无对白。
- 场景：左侧分叉树、右侧低灌木、后方弯曲小路、左上方日光。

**验收标准**：角色各自形态完整、装饰颜色正确、背景不复杂；狐狸在同框里约为老虎一半高。确定后保存原文件与SHA256，不再为每镜重新设计人物。

### 阶段2：先生成声音，测量每镜所需时间

1. 查官方系统音色列表，为狐狸、老虎、旁白各挑一个支持该模型且用途合规的音色。[S8]
2. 同一个角色全片固定一个 `voice` ID，保存到 `records/voices.json`。角色名字不能直接当API音色ID。
3. 只把 `shots[].text` 送TTS，不把“老虎：”“近景”“得意地”等舞台说明读出来。
4. 一镜一个WAV文件；默认普通话、自然语速，不加音乐，不克隆真人。
5. 表演提示可指导选择音色和试听。不要把JSON中的自然语言 `emotion` 直接当成任意API参数：该模型系统音色的 `instruction` 有规定格式和适用限制；不确定就不传。[S7]
6. 测量真实配音长度 `a`，镜头时长采用 `max(计划时长, a+0.6秒)` 并向上对齐帧。前0.2秒留入点，其余余量留尾音。
7. 若单镜超过12秒，先排查是否把说明也念了；必要时重配或拆镜，不硬截台词。若全片超过105秒，检查不自然停顿，重新合成偏长句，不全片粗暴加速。

官方已核对的请求形状（执行者配置好环境后使用；不是现在已执行）：

```bash
# TTS_URL 使用自己业务空间/北京地域对应的官方 SpeechSynthesizer 地址。
# 不把API Key直接写入命令文本，避免进入终端历史。
curl --fail-with-body --silent --show-error "$TTS_URL" \
  -H "Authorization: Bearer $DASHSCOPE_API_KEY" \
  -H 'Content-Type: application/json' \
  --data-binary @records/tts-request.json
```

`records/tts-request.json` 示例结构：

```json
{
  "model": "cosyvoice-v3-flash",
  "input": {
    "text": "抓到你了！今天的晚餐有着落了！",
    "voice": "longanyang",
    "format": "wav",
    "sample_rate": 24000
  }
}
```

`longanyang` 是官方文档中的示例ID，不代表已试听批准为老虎声音。执行者需按实际音色映射替换。响应是JSON而非WAV本体；按官方响应结构取得音频URL后下载为 `assets/audio/01.wav`，检查HTTP状态、文件类型、音轨和时长。非实时下载URL有效期为24小时，应立即保存。[S7]

### 阶段3：用参考图逐镜生成画面

每镜输入顺序固定：该镜出现的角色参考图（1–2张）+森林参考图（1张），总共2–3张，不超过4张。单人镜头不提供另外两人的图，避免模型自动“合影”。

**通用分镜提示词模板**：

```text
生成本片的一个独立镜头，竖屏9:16，单幅画面，不要漫画分格。
[统一画风]
参考图1是[角色A]；参考图2是[角色B或森林]；参考图3是[森林，如存在]。
严格保留角色毛色、面部设计、围巾/马甲/背包、尾巴数量；不要交换角色服饰。
[逐一重复本镜角色设定]
[读取本镜visual，保持人物左右关系和视线方向]
主要角色脸部在画面中央安全区域，下方20%避免关键动作，方便后期字幕。
图中不要写任何文字；只出现本镜指定角色；光线、画风与森林参考图一致。
```

第06镜专用要求：狐狸在画面左前，老虎在右后，两者面向左；不能变成老虎领路。第08镜必须让老虎清楚可辨，让观众理解小兔真正怕谁。**这两个镜头是故事因果验收点，不能只凭“图片很好看”通过。**

`wan2.6-image` 使用图像编辑模式时：[S6]

- `parameters.enable_interleave=false`；必须传1–4张图，文生图另用 `wan2.6-t2i`。
- 显式设置 `n=1`，避免默认多图增加费用。
- 建议 `size="1080*1920"`，模型可能输出接近要求的16倍数尺寸，最终由合成器裁切至1080×1920。
- 可设置 `prompt_extend=false` 降低自动改写设定的机会；是否有帮助需看样片。
- `input.messages[].content` 中放参考图的 `image` 和一个 `text` 对象；按官方支持格式传可访问URL或Base64，不填本机磁盘路径。
- 同一个seed不保证完全相同，更不保证角色一致；真正的控制来自固定参考图、构图约束和人工/视觉检查。
- 同步/异步接口路径不同。使用异步时保存 `task_id` 并查询原任务，不因等待就反复创建新任务。
- 成功取得临时结果URL后立即下载。对每个文件检查图像可解码且内容不是报错页面。

### 阶段4：先完成样片再批量

先只做01–03镜，自动合成样片。样片通过后再生成04–15镜。这可以同时验证：角色一致性、声音、中文字体、字幕安全区、构图裁切及合成工具，而不先把全片预算花掉。

执行者每张图片自行检查：角色数量、颜色、服装、肢体、画面说明、字幕区域。若使用视觉模型评分，它只是辅助判断，不等于客观证明；关键镜头需实际看图。

## 7. 自动合成：这些命令是本交付实际支持的

### 7.1 先校验15张图和15段声音

在 `manju-guide` 目录执行，路径参数按本机真实情况填写：

```bash
.venv/bin/python render.py \
  --project production.json \
  --assets assets \
  --font '/实际路径/中文字体.otf' \
  --check-only
```

成功表示素材存在、图像可读、音频有有效时长、字体可加载等技术前提通过；**不表示台词内容、角色一致性或版权已经通过**。

### 7.2 生成前三镜样片

```bash
.venv/bin/python - <<'PY'
import json
from pathlib import Path
p = json.loads(Path('production.json').read_text(encoding='utf-8'))
p['shots'] = p['shots'][:3]
Path('sample-project.json').write_text(json.dumps(p, ensure_ascii=False, indent=2), encoding='utf-8')
PY

.venv/bin/python render.py \
  --project sample-project.json \
  --assets assets \
  --font '/实际路径/中文字体.otf' \
  --out sample
```

脚本按所选项目的镜头校验，不要求样片阶段已有后12镜。样片素材须是真实批准的角色图与配音，不能拿测试色块或提示音当样片。

### 7.3 样片批准后合成全片

```bash
.venv/bin/python render.py \
  --project production.json \
  --assets assets \
  --font '/实际路径/中文字体.otf' \
  --out output
```

脚本会：
1. 根据每段真实配音计算时长，不截断台词。
2. 将图片统一缩放、居中裁切至目标竖屏；做约4%的缓慢推近/拉远。
3. 在固定屏幕位置绘制中文字幕和AI辅助生成标识；字幕不会跟随画面放大。
4. 将每段音频前移出0.2秒空隙，尾部补静音以匹配镜头。
5. 拼接全片，做响度处理，输出H.264/AAC MP4。
6. 输出整句SRT、实际时间线、封面基础帧、技术检查报告。
7. 完整解码一次输出，检查是否存在解码错误。

输出非空时默认拒绝覆盖；执行者确认可以覆盖派生文件后，可增加 `--force`，或使用新的输出目录。不会修改原始素材。

### 7.4 交付文件

```text
output/final.mp4         # 烧录字幕与AI标识的正式候选片
output/subtitles.srt     # 镜头级整句字幕；不是语音强制对齐结果
output/timeline.json     # 每镜真实起止时间
output/cover.png         # 第1秒提取的无标题封面基础图，不是自动设计好的营销封面
output/qa.json           # 技术检查＋尚需人工判断的项目
output/build/            # 中间片段、固定字幕透明图、拼接清单
```

`render.py` 不包含：模型API调用、配音识别、自动角色评分、背景音乐混音、口型生成、剪辑器工程文件、图生视频或自动发布。需要这些功能时不能误认为现有脚本已提供。

## 8. 让你少参与的关键：执行者遵循这张状态表

| 阶段 | 输入 → 输出 | 谁决策 | 通过条件 | 失败后怎么做 |
|---|---|---|---|---|
| PRECHECK | 本指引、账号、预算 → 环境与授权记录 | 你一次确认，执行者检查 | 可调用服务、可渲染，计费已知 | 登录/授权问题只集中询问一次 |
| SCRIPT_LOCKED | JSON → 锁定剧本 | 默认不再问你 | 15镜、90秒计划、故事完整 | 修结构不擅自换题材 |
| ASSETS_READY | 角色/场景设定 → 4张参考资产、3音色 | 执行者初筛 | 风格和辨识特征一致 | 单资产最多重生成2次 |
| SAMPLE_REVIEW | 前3镜 → 样片＋拼图 | 你第二次确认 | 图、声音、字幕都能接受 | 按反馈只改对应资产 |
| BATCH_READY | 已批风格＋后12镜 → 全量素材 | 执行者自动推进 | 15图15音轨、关键因果镜头通过 | 定位镜号重做，不全量重来 |
| RENDERED | 全量素材 → 成片及sidecar | 执行者 | 技术检查全部通过 | 修合成参数，不重付生成费 |
| FINAL_REVIEW | 成片→审看记录 | 你第三次确认 | 内容、权利、标识通过 | 只返工不合格镜头 |
| APPROVED/PUBLISHED | 通过版本→归档/平台提交 | 你确认是否公开 | 已归档；发布则有真实链接/状态 | 平台审核不通过时按原因修正 |

### 自动化适配器应怎么实现（交给执行代理，不要求你手写）

本交付没有把服务商API封装成“万能生成命令”。执行者如采用API批量生产，按官方文档实现一个本地适配器，明确区分以下步骤：

```text
读production.json
→ 校验已获批准的预算、地域、模型、音色映射
→ 创建/读取records/jobs.jsonl
→ refs阶段：生成并下载角色/场景参考图
→ sample阶段：只生成01–03的音频和图像，调用render.py
→ 等待样片批准（批准状态单独记录，不伪造）
→ batch阶段：仅处理未通过的04–15素材
→ render阶段：调用render.py，读取退出码及qa.json
→ review阶段：输出需人审的清单，不自行宣称质量通过
```

每个素材以 `镜号+类型+模型版本+提示词哈希+参考图哈希+音色ID` 作为缓存键；保存任务ID、请求ID、生成参数、下载位置、状态和估算成本。模型输出只能作为素材或数据，不执行其返回文本里的命令。

**重试策略**：
- 限流/可恢复网络错误：退避等待，例如10、30秒，最多2次；若已有任务ID，先查询同一任务状态。
- 请求超时且不清楚是否已被计费：标记状态未知、核查控制台或查询原任务，不立刻重新提交。
- 401/403/余额不足/模型无权限：停止相应调用，不循环消耗；只向你集中提出需要的账号操作。
- 图片质量不合格：同一素材最多再生成2次；多角色仍崩坏则改为单人近景与反应镜，保持台词和因果；大改分镜要记录。
- 内容安全拒绝：把非必要危险表达改成温和表述并再次校验故事，不规避服务安全机制。
- 预算：每次调用前计算“已花费用＋运行中任务预留＋本次最坏费用”，超过授权上限就停止新请求。账单可能延迟，不把余额告警当作即时硬上限。

**正常情况下不问你**：镜头文件命名、URL下载、音频格式转换、字幕换行、局部裁切、在约定内的重试。
**必须问你**：新购买/超预算、变更题材或全片风格、使用不明权利素材、登录验证、公开发布。

## 9. 花多少钱、多久，怎样避免越做越贵？

核对时官方北京地域列价：[S9]
- `wan2.6-t2i`：0.20元/输出图片。
- `wan2.6-image`：0.20元/输出图片。
- `cosyvoice-v3-flash`：1元/万输入字符。

这些是检索时的地域/模型价格，不是长期报价；开工重新核价。免费额度有条件和有效期，估算不默认免费。

### 本案模型费用的可复算估计

基础19张图 = 3张角色 + 1张场景 + 15张分镜。首轮约 `19 × 0.20 = 3.80元`。

- 允许部分重绘时按25–40张估计：图像约5–8元。
- 若每张都用完“首次＋2次重试”，最多57张：约11.40元。
- 15句对白加试听、重配，按不超过3000计费字符估算：TTS约0.30元。
- **以上只覆盖这两个媒体模型**；不含执行代理/语言或视觉模型Token、订阅会员、字体/音乐许可、人工、网络和设备成本。
- 20–50元是可选择的媒体试做预算缓冲，不是你已授权支出，也不是整部作品必定只花这些钱。

### 时间安排（经验规划，不是服务SLA）

首次账号与环境准备 → 约15–30分钟人工；素材生成与返工 → 通常数十分钟到数小时等待；样片审核 → 约5分钟；本地渲染 → 视设备与分辨率可能数分钟到数十分钟；终审 → 约5–10分钟。初次踩环境问题可能更久。

最省成本的顺序不是“先把全片生成再挑”，而是**19张基础资产上限思维、先17秒样片、只重做坏镜头**。

## 10. 验收、发布与归档：怎样才算整部完成？

### 10.1 技术验收（执行者自动做）

- [ ] 15张有效画面、15段有效配音；ID唯一，时长为正，没有漏镜。
- [ ] `qa.json` 编码、尺寸、像素格式和时长检查均为true；完整解码通过。
- [ ] 总时长目标90–105秒；若超过范围，记录原因，不能声称与计划完全一致。
- [ ] H.264 / AAC、1080×1920、30fps，播放器正常从头到尾播放。
- [ ] SRT条数15、起止递增不重叠，时间轴与视频相符。
- [ ] 最后一句没有被切掉，尾部保留停顿，不出现意外空黑结尾。
- [ ] 用 `ffmpeg -i output/final.mp4 -af loudnorm=I=-16:TP=-1.5:LRA=11:print_format=json -f null -` 复测响度；注意输出中的 `input_i` / `input_tp` 才是被测成片数值，不把目标值当成实测值。短片可能有少量偏差，必须试听无爆音、无忽大忽小。

### 10.2 内容验收（人或执行者先审，你终审）

- [ ] 狐狸始终绿围巾，老虎始终蓝马甲，小兔始终红背包；颜色、体型不漂移。
- [ ] 同框时狐狸在前、老虎在后，小兔逃走是因为看到老虎。
- [ ] 第01–03镜立即建立“要被吃→虚张声势”的冲突。
- [ ] 第12镜脱身、第13–14镜点题、第15镜收尾，非只生成一段预告。
- [ ] 配音逐句核对JSON；特别听“百兽”“天帝”“狐假虎威”，无漏读、错读或读出说明。
- [ ] 字幕没有方框/乱码，不遮脸，手机上可读，未被目标平台底部和右侧按钮遮挡。
- [ ] 无畸形多尾、多肢、角色融合、突然多出角色；无需追求每片树叶一致。
- [ ] 没有误导成“利用他人权势欺压别人很值得赞扬”；结尾明确揭穿借势。

### 10.3 发布包装

封面建议用第01镜或第10镜裁图，标题由编辑器或Pillow后期加，别让图像模型生成汉字：

- 主标题：`狐狸凭什么吓跑老虎？`
- 小标题：`90秒看懂狐假虎威`
- 如果实际成片明显不是90秒，改为`一集看懂狐假虎威`。
- 封面与标题不写“全网第一”“百万播放”等未验证说法。

发布文案示例：

> 一只小狐狸，怎么让老虎主动让路？依据《战国策》古代故事重新改编的轻喜剧漫剧。画面与配音采用AI辅助制作。
> #狐假虎威 #成语故事 #原创改编 #AI漫剧

发布前逐项核对目标平台的最新规则：AI内容声明、少儿/亲子标签、原创标记含义、音乐/字体权益、是否涉及网络微短剧相关审核或备案要求。不同平台与内容形态不能一概而论；本文不替平台作分类或免审承诺。不得删除服务商/平台强制要求保留的标识或元数据。

### 10.4 “完成”的两级定义

- **制作完成**：完整片可播放，故事闭环，15镜齐全，技术检查与人工终审通过，视频/字幕/封面/素材/生成记录已归档。
- **发布完成（仅在你要求公开发布时）**：实际提交成功，有平台返回的作品链接或作品ID及审核状态；“文件导出了”“点了提交”都不能冒充审核通过。

归档至少保留：最终MP4、SRT、封面、JSON、定妆图、15镜原图与原音频、模型版本/音色ID、提示词与参考图哈希、用量、授权凭据、人工审片记录。不要把API Key归档进去。

## 11. 可直接交给执行代理的整包指令

3. 按官方文档实现必要的本地API适配，保留任务ID、请求ID、用量和下载记录。
   现有render.py只负责合成，不能把它当作图片或语音生成器。
4. 生成并冻结3角色+1场景参考图；选定三个合规系统音色。
5. 只生成前3镜图像/配音，用render.py合成样片。
6. 一次提交角色拼图、声音试听和样片，等待用户批准后才批量生产。

样片通过后：
7. 根据production.json生成其余素材，使用角色/森林参考图，不独立文生每一镜。
8. 按ID保存到assets/images/NN.png和assets/audio/NN.wav；缓存通过素材。
9. 执行输入检查、全片合成、全量解码、响度复测和内容初审。
10. 输出final.mp4、subtitles.srt、timeline.json、cover.png、qa.json、
    制作记录和素材授权清单。封面基础帧另加清晰中文标题，保存带标题版本。
11. 只把最终成片和必须决定的异常交给用户，不让用户逐镜复制粘贴。

故障规则：最多对单个素材再生成2次；只修坏素材，不全片重来。
已提交异步任务先查原任务，不因超时重复购买；预计费用含运行中预留。
超预算、无权限、版权不明或需要公开发布时暂停询问。
不得伪造试听、视觉验收、用户批准或发布状态。

默认不公开上传；用户终审通过并明确授权后，才能走平台发布步骤。

## 12. 不用API时的备用路径

如果你不愿配置开发接口，可让制作人员使用已有合法账号的创作平台或剪辑器执行同一套JSON：
1. 在支持参考图的图像工具内固定角色与场景，按镜号批量制作。
2. 在能下载音频且许可合适的TTS工具中，固定三种声音，逐句导出WAV。
3. 仍用 `render.py` 合成，或在剪辑器内将图片、配音按编号排列。
4. 人工将镜长设为配音长+余量，字幕从JSON复制并对齐；画面推近约4%。
5. 完整审片后发布。

这条路径可行，但没有API或受支持的批处理时，逐图下载、命名和对齐仍有人工作量；**不能声称它与主方案一样省参与**。不要假设任意剪辑器会员含免费模型额度，也不要假设产品存在未核实的“全自动漫剧”按钮。
